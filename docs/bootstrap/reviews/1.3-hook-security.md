# Instadash 1.3 hook review — 2026-11-17

Scope: static review of the changed runtime, project-local watcher, native matchers, and
version-sync traversal. Local release preparation only; nothing published or deployed.

No Critical/High findings remain in this review. The watcher is a same-user development helper,
not a security boundary against code already running as that user.

- Root boundaries: absolute/parent paths, symlinks and credential/state directories are rejected.
  Watcher storage, locks and logs cannot redirect writes outside the project through symlinks.
  Version syncing prunes dependencies and directory/file symlinks before reading settings.
- Inputs: native session IDs are hashed; filenames use JSON/NUL-delimited pipes, never shell
  interpolation. SQLite values use parameters. Directory exclusions are validated and additive.
- Git ignore matching: one isolated local metadata directory, no changes to component Git roots,
  no global/system configuration, credential inspection, external fetches or custom glob parser.
- IPC: a project/UID-specific Unix socket checks peer UID. The daemon has a private umask,
  bounded input size/event batches/cache, no worker pool, and blocks in select when idle.
- Correctness: durable revision cursors recover deletions after restart. History loss/failure
  with an active cursor is explicit rather than silently clearing the handoff gate. Formatting
  is serialized across sessions, preserves pre-formatter dirty timestamps, and touches eligible
  changed files only. Legacy baselines do not misclassify existing newly-covered docs as edits.

Validation: isolated demo passed Git-ignore/negation/nested-rule/dependency checks, formatting,
handoff, existing-baseline conversion and restart/deletion recovery. It observed zero idle CPU
ticks over 300 ms, zero full rescans during ordinary edits/reads, and a 101-byte cursor.
`git diff --check` and syntax compilation passed. The full scratch-install, relative-link and
integration suite is deferred by the owner until resource capacity is available; it must not be
reported green before it runs. No new dependency was installed; external scanners were not run.

Native activation: on-disk runtime changes load on the next registered hook invocation. An
already-running invocation finishes with its old code. New matcher entries require the native
client's normal configuration reload/trust lifecycle; fixture tests cannot establish activation.
