# Backend Scaffold (Django + DRF)

> The **reference implementation** of the backend architecture guidelines, stored as Markdown.
> Every fenced code block under a `### \`path\`` heading is the **exact, complete content** of that
> file, relative to the **backend repo root**. An agent bootstrapping a new backend materialises
> these blocks verbatim (substituting placeholders), in the order below. There is no source code in
> this base repo — only these documents.
>
> Architecture rationale lives in [`../../architecture-guidelines/backend/`](../../../architecture-guidelines/backend/);
> this folder is the "copy this" counterpart. If the two ever disagree, the
> [canonical decisions table](../../../architecture-guidelines/README.md#canonical-decisions-these-win-over-any-older-wording)
> wins — fix whichever page is wrong.

## Placeholders

Replace these everywhere while materialising. Values come from the project's `DOCS.md`
(filled in at Bootstrap) — never invent them, never hard-code a company name.

| Placeholder | Meaning | Example |
|-------------|---------|---------|
| `<project_slug>` | lowercase, hyphen/underscore-free-ish identifier used for the Poetry name, DB name, RabbitMQ user/vhost, image path | `acmecrm` |
| `<PROJECT_NAME>` | human product name (API title, email subjects) | `Acme CRM` |
| `<LEGAL_ENTITY_NAME>` | legal/company name from `DOCS.md` — goes **only** into `.env` (`LEGAL_ENTITY_NAME`), never into code | — |
| `<registry>` | container registry host/namespace | `registry.example.com/team` |
| `<frontend_port>` / `<backend_port>` | host ports from `DOCS.md` (the container always listens on **8000**) | `5173` / `8000` |
| `<INSTADASH_BASE_VERSION>` | the AI-base version this project is generated from — read from `docs/bootstrap/VERSION` at bootstrap; rewritten only by the upgrade flow | `1.0` |
| `<Project Name>` / `<Legal Entity Name>` / `<YEAR>` | fill-ins of the **license header** (product name, legal entity from `DOCS.md`, current year) | — |

### License header

Every code block for a file that can hold comments (`.py`, `Makefile`, `Dockerfile`,
`.dockerignore`, `.gitignore`, `.env.example`, `pytest.ini`, `*.toml`, `*.sh`, `*.yml`) starts with
the project license header (after a shebang / `# syntax=` line when present, before any module
docstring). Materialise it with the three header placeholders filled. **Apps you create with
`startapp` — now and later — get the same header prepended to every generated module** (`apps.py`,
`models.py`, `admin.py`, `views.py`, `tests/…`, `__init__.py`), **except migrations**, which stay
exactly as `makemigrations` writes them. JSON files cannot hold comments and get no header.

### Base lineage (do not remove)

`settings/base.py` carries `INSTADASH_BASE_VERSION` and `apps.core.middleware.InstadashVersionMiddleware`
stamps it on every response as `X-Letstream-Instadash-Version`. Both are managed by the
bootstrap/upgrade flow — see [core-app-reference](../../../architecture-guidelines/backend/core-app-reference.md).

Tenancy: `DOCS.md` records **single-tenant** or **multi-tenant**. Set `TENANCY_MODE=single|multi`
in `.env`. For **single-tenant**, skip [organization.md](organization.md) entirely (don't create the
app); everything else is identical — see
[multi-tenancy §0](../../../architecture-guidelines/backend/multi-tenancy.md#0-single-tenant-vs-multi-tenant).

## Materialisation order (exact commands)

Prerequisites: Python ≥ 3.12 (use the latest the machine has), Poetry 2.x, a reachable PostgreSQL,
Redis and RabbitMQ (local install or the `infra/` compose stack — see [infra](../../../infra.md)).
Run every command from the paths shown; **never hand-write `apps.py` or migrations**.

```bash
# 1. Repo + Poetry project -------------------------------------------------------
mkdir -p <project_slug>-backend/app && cd <project_slug>-backend
git init
#    write: .gitignore, VERSION                     (project.md, docker.md)
#    write: app/pyproject.toml, app/poetry.toml      (project.md)
cd app
poetry install --with dev --no-root -q              # creates app/.venv and poetry.lock

# 2. Django project package (generated, then settings are replaced) -----------------
poetry run django-admin startproject app .          # → app/manage.py + app/app/
rm app/settings.py                                  # replaced by the settings/ package

# 3. Apps — created with the CLI (django-admin, so it works before settings exist) ---
mkdir -p apps/core apps/accounts
touch apps/__init__.py
poetry run django-admin startapp core apps/core
poetry run django-admin startapp accounts apps/accounts
# multi-tenant only:
mkdir -p apps/organization && poetry run django-admin startapp organization apps/organization
# startapp creates tests.py — delete it; tests live in the tests/ package:
rm -f apps/*/tests.py
#    prepend the license header to every generated module (not migrations) — see above

# 4. Replace/add module files from the docs (overwrite generated apps.py/models.py/…) -
#    settings.md → app/app/**      core.md → apps/core/**      accounts.md → apps/accounts/**
#    organization.md → apps/organization/** (multi-tenant only)
#    project.md → pytest.ini, conftest.py, Makefile, .env.example
cp .env.example .env                                # then fill real local values (gitignored)

# 5. Migrations — generated by Django, in dependency order ------------------------
poetry run python manage.py makemigrations core
poetry run python manage.py makemigrations accounts
poetry run python manage.py makemigrations organization   # multi-tenant only
poetry run python manage.py migrate
poetry run python manage.py check

# 6. Admin user, then the gates -----------------------------------------------------
poetry run python manage.py createsuperuser
poetry run ruff check --fix . && poetry run black .  # normalise import order/format once
make lint
make test
```

Then run the stack **backgrounded** (never in the foreground — see `AGENTS.md`):

```bash
nohup poetry run uvicorn app.asgi:application --host 0.0.0.0 --port <backend_port> > .dev.log 2>&1 &
nohup poetry run celery -A app worker -Q default,emails,maintenance -n local@%h --without-gossip --without-mingle > .celery.log 2>&1 &
curl -s localhost:<backend_port>/api/health/        # {"status": true, "data": {...}, "version": "0.1.0"}
```

All API routes live under **`/api/`** (`/api/health/`, `/api/accounts/…`, `/api/organization/…`,
`/api/docs/` when `DEBUG`) because the Vite dev proxy, the frontend nginx and the infra compose
forward only `/api/` and `/ws/` to the backend. The Django admin sits on its obfuscated
`ADMIN_URL` path and is reached on the backend port directly.

In deployed environments each queue gets its own worker and the web command is supplied by the
compose file / orchestrator — see
[containerization-and-deployment](../../../architecture-guidelines/backend/containerization-and-deployment.md).

## After bootstrap

- Feature apps: `mkdir -p apps/<name> && poetry run python manage.py startapp <name> apps/<name>`,
  set `name = "apps.<name>"` + `label` in its `apps.py`, append to `INSTALLED_APPS` in `base.py`,
  `include()` its `urls.py` in `app/urls.py`, then `makemigrations <name>`.
- Tenant models extend `OrgScopedModel`; every other model extends `TimeStampedModel` or
  `UUIDTimeStampedModel`. Every tenant model gets a cross-tenant isolation test
  ([testing](../../../architecture-guidelines/backend/testing.md)).
- Register new models with `auditlog` ([audit-logging](../../../architecture-guidelines/backend/audit-logging.md)).
